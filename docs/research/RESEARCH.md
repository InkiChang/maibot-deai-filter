# MaiBot 拟人系统参考仓库调研记录

本文件记录与 MaiBot 拟人系统相关的公开仓库调研结论。仅将其作为设计启发；遵守各项目许可证，不复制未授权代码、文本或个人数据。

## 已核对项目

### MaiBot 专项：tutukenny818-oss/Improvements-to-QQbot-dafeiyu-memory-and-language-systems
- 面向 MaiBot 的改造/故障复盘集合；主张“不该说时不说，被点名必回”，有 I1/I2/S1/S2 门控；重视真实 Planner/Prompt 快照和实际运行态，不只 grep 源码。
- 记忆重点在评测与证据链：覆盖面、检索召回、噪音、无证据 claim；12 个固定题、五类问题。复盘指出两条写路径规则不一致会让模型编造数字写进 relations。规则：数值要能回指原文证据；不要未验证就删边/批改事实。
- 群聊多 bot 防互相接话；bot 消息不入记忆但指令可白名单处理。
- 许可分层：文档 CC BY-NC-SA 4.0，ops MIT，代码改动受 GPL-3.0。

### dsh-HCEM (WoFeng3094172/dsh-HCEM)
- HSL-Chroma 情绪记忆/推理系统；情绪性格随用户记忆变化；storageDomain 与宿主原生工作区分离。
- 项目自称仅适用于陪伴，并允许情绪极化产生轻度幻觉；MaiBot 应借鉴状态隔离，不应接受幻觉/不实记忆做“拟人”。

### dating-ai-bot (2910855245/dating-ai-bot)
- 把像真人当可测量工程指标，有真实聊天语料统计基线、表层结构指标和拟人度 harness；强调不要把 AI 腔压成只会“嗯哦”的木头。
- 可借鉴离线回归评测、分阶段判定/生成和真实语料统计；其未脱敏第三方聊天记录未授权公开，绝不可拷贝使用，需自行合法脱敏收集或合成测试。

### memory-card (hchh7wby2s-oss/memory-card)
- Codex Skill，GPL-3.0；艾宾浩斯遗忘曲线、本地可读文件、只记录真实说过的话、可编辑/删除。
- 借鉴透明可编辑和淡忘概念即可；不直接移植 GPL 代码或重造 A-Memorix。

### VitaLoom (Void-Creator-Deity/Lotucosm-VitaLoom)
- MIT；PVAEC：感知→记忆→尝试→验证（新感知）→再记忆。主仓是仿生运行时/仿真环境；MaiBot 仅借鉴“状态变化需验证”的闭环，不搬仿真 runtime。

### ai-agent (big-cute-orange/ai-agent)
- README 虽以 AI Agent 平台命名，实际将仓库描述为 Turborepo/Next.js/Hono/Cloudflare 全栈平台脚手架。已核查 98 项文件树、API 路由及 web 首页：API 目前只有 `GET /health`、`POST /rpc/system/ping`，首页只调用 ping；未发现聊天/LLM、人格、记忆或情绪实现。无声明许可证；不借鉴拟人机制、不复制代码或文本。

### human-speak-prompt (lattes3690/human-speak-prompt, MIT)
- 指代/虚实语境/语气词/意象；“你现在不是AI”“少用我/你直给”“不用逻辑词”等过度规定易导致欺骗、编造、可读性下降，不照搬。

### make-ai-speak-human (nikonikoni4)
- 14 条可读性规范：明确句子成分、短句、简单句、少术语和装饰比喻、先答后解释；作者承认可能压缩机制/边界细节。
- 适合技术解释，不宜强行用于亲密聊天；应按场景切换。

### dafeiyu_human (Caoran1314, MIT, AstrBot)
- 三段管线：请求前随机延迟；响应后去 AI 腔/书面改口语/注错字；装饰阶段一句一行拆分。可借鉴分阶段处理与配置化；错字、随机延迟有信任与可用性副作用，默认关闭或可选。

### zhiyi (hesanyue50-lang/zhiyi, MIT, Android Kotlin)
- 人格维度：身份/使命/关系/底线/向往/阴影；向往+阴影比堆性格形容词更有稳定张力。
- 记忆区分重要度（初始重要性）和清晰度（随时间衰减，重要者衰减慢，底线0.15），可保留模糊回忆。
- 人格修改追加版本、回滚保留历史；状态调节语气和主动性；本地优先。
- 借鉴人格维度、重要度/清晰度分离、版本审计；防操纵/依恋倾向拟合用户。实现平台与 MaiBot 不同。

### hermes-alive (Cimen101/hermes-alive, MIT)
- 分模块生命状态机：clock/energy/stress/boredom/PAD emotion/bond/drive/coordinator；状态与 DAG 记忆存 SQLite，FTS5/FAISS 检索融合，容量淘汰与每日淡忘。
- 后台情感巡查使用 auxiliary 模型；Hook 覆盖生成前后、会话生命周期、工具后处理和输出自检；具人格护栏与 Dashboard。
- 作者报告 21 套端到端/数值/长跑测试及干净容器安装通过，属于仓库自述、非独立审计。值得借鉴状态模块化、独立低成本巡查、自检和测试门槛，不要照抄其自建长期记忆（MaiBot 已有 A-Memorix）。

### N.O.R.A.Core (captain-wangrun-cn/N.O.R.A.Core, BSD-3-Clause)
- 多平台陪伴框架：把交流切成消息段；近期保留更多原文，较早内容逐层摘要和归档，每日摘要；Markdown 管可编辑人格/用户档案/日程，SQLite 管原文、摘要槽与滚动归档。
- 主动关怀与明确提醒分开，考虑在线状态、半在线收段、频率与打断；强调摘要失败保护、RAG 不等于全记住。
- 借鉴消息段语义、记忆分层、可维护文件职责、主动行为护栏；其框架规模与 MaiBot 插件非同构，整体移植不合适。许可证 BSD-3-Clause。

### astrbot_plugin_autonomous_social (naliling, AstrBot)
- 主动消息必须有具体由头：攒念头只决定何时评估，不决定必发；发送路径包含对象筛选、时段、冷却、频率、关系档、模型否决和验收，失败不发并保留念头。
- 事件类型包括未完话题、追问、回访、问候、主动收场；群/私聊分开控制，有事件去重、每日限额、拒绝后停止、主动消息记账。README 提醒生成素材需注明“未必真做过”，避免把虚拟生活冒充事实。
- 长期记忆通过独立插件桥接，生成前读取个人记忆摘要、发送后回写，仅私聊。MaiBot 可借鉴多重门控、去重、候选生成与发送记账，不照搬 AstrBot API。
- 版本 v2.2.49，AstrBot 4.24.2+；主动场景默认谨慎，群聊与私聊隔离。许可需以仓库 LICENSE 核验后再决定代码借鉴。

### MaiWeave (ilworkcn/MaiWeave, GPL-3.0；README v0.12.0)
- 持续角色生活引擎：日程/作息/天气地点/活动状态/精力心情/关系与主动关心/阅读日记梦境/空间分享；生活有计划、选择与事件连续性，能结合 MaiBot 人物画像。
- 用户现装 v0.11.8 的实测：环境资料可能跨所有会话注入；模拟经历不写 A-Memorix，但生活上下文仍参与提示。新 README 说明 v0.12.0 经历来源可追溯并与原生记忆衔接；不能把 0.11.8 实测直接外推到新版，升级前应比对变更并抽查真实 prompt。
- 仅借鉴生活状态、日程和事件连续模型；本项目自行设计数据模型与实现，不依赖 MaiWeave 代码、运行时或数据库，也不并行保留双生活注入。可独立实现为兼容微信的角色生活引擎。

### private-humanizer (DeepSeek-V4-Pro/private-humanizer, MIT, v1.6.1)
- Hook 在 Planner/Replyer 注入时间、虚拟日程/生活环境、画像和风格规则；Replyer 后有事实/风格守卫与可选主动续话。事实/记忆守卫是规则级且只覆盖表达学习特定 Hook，并非全局记忆防护；虚拟状态须标明非事实。
- 默认 dry privacy logging 不存原文，启用 rewrite pair 需临时排障；配置要求目标用户，提示约 1500–3000 字符可能增加 token。Hook 返回 kwargs 要保留原键，避免插件互相覆盖。
- 本机既有审计发现 style_guard 硬截断风险；与 antibait 重试、MaiWeave 主动分享/自研决策并存时需关闭重复主动/重复改写，验证最终 prompt。

### maibot-antibait (TommyAAKK/maibot-antibait, MIT, v2.0.0)
- 针对 AI 八股/过长/附和服软/标点和跨回复重复评分；命中后打回 Replyer 重生成一次并择优，区分硬伤和风格问题，并对复读、总结要求、玩梗、短答做豁免；dry_run 默认开，作者建议先观察 2–3 天。
- README 自述基于 818 份真实 prompt 快照、盲评和回归套件；参数需按本 bot 基线校准。短句不等于拟人，保留角色口癖；重试带模型成本，硬故障与风格重试应分级处理。

### life-behavior-reference (riesaexe/life-behavior-reference, GPL-3.0)
- MaiBot SDK 命令插件，365 条中文行为指南/12 大类/31 小类，四档信息密度，按用户命令检索并用转发卡片呈现；不是自主生活引擎，也不是回复决策器。
- 仅借鉴分类、按需检索、信息密度分层和微信交互思路；行为条目与实现代码由本项目自行设计编写，不复制仓库文本/代码。委员会叙事及其研究声明不可当真实研究或事实。

### JEV/SubQ 决策层（规划建议）
- 若 JEV 指 Judge/Evaluate/Verify，建议只让 SubQ 对每个入站事件输出受 schema 约束的决策，不让它生成最终聊天文本：`reply | brief | hold | escalate`、理由码、置信度、TTL、是否需要原生记忆检索/生活上下文、可用事实引用 ID。
- 确定性规则先行（平台/黑名单/明确点名/指令/安全边界）；SubQ 处理语用与角色状态。明确提问、点名、承诺/紧急求助不可由低置信度决策静默吞掉；低价值群聊可 hold。超时、异常、非法 JSON、SubQ 不可用时 fail-open 到 MaiBot 默认 Replyer；审计只留理由码/耗时，不默认存私聊原文。
- 输入最小化：当前消息、近邻上下文、平台/群私聊类型、状态摘要、相关原生记忆检索结果；不把整库或完整生活历史传给 SubQ。决策结果需短 TTL，按 event/message ID 幂等，避免重复推理/发送。
- 分清层次：SubQ 入站门控决定“是否调用 Replyer/简短回应/暂缓”；Replyer 仍负责回答；antibait 是生成后质量重试；humanizer 是提示/守卫；MaiWeave 是生活模拟。多个层不能都重写或各自触发主动消息。
- MVP 先影子模式记录 SubQ 判决但不拦截，离线对照人类标注，再小范围启用 hold；测误沉默率、明确问题漏答率、群噪音拦截率、延迟/成本、拒答/求助召回。主动消息候选之后另开决策路径，默认不与入站回复共用简单阈值。

## 调研结论
- 已逐一检查 Edge 中的 GitHub 标签；本轮依据 README、项目介绍与技术文档，未逐文件源码审计，也未独立复现各项目测试。
- 推荐顺序：MaiBot 专项复盘的私聊入口硬闸与记忆证据评测 → 原生人格读取及短期状态机 → 生成前精简状态注入、发送前验收 → 再考虑生活资讯、梦境等低频模拟；稳定人设不另建插件版本账本。
- A-Memorix 保持真实事实唯一源；官方 SDK 未公开专用读写代理，勿直接改其内部数据库。实施前应在当前 1.4.5 实例验证 Hook/SDK 参数。

## 融合架构（用户补充要求）

### 世界模型：受控虚构，不等于现实事实
- 允许角色拥有独立模拟生活，生活事件在角色自身世界中可作为连续经历；但必须带来源/类型标签：`user_fact`（用户明确提供）、`observed_fact`（有现实证据）、`persona_fiction`（角色模拟生活）、`inference_candidate`（推测待核实）。
- 角色可以自然谈及虚构经历，但不能把它宣称为现实可验证的事实（例如声称真的在某地、真实看见天气或完成现实行动）。被问“这是真的吗/你真的做了吗”时需坦诚说明是角色模拟；模拟不能篡改用户事实、现实日期/地点、承诺和安全边界。
- 虚构生活的“幻觉”应是受约束世界生成：时间/地点/日程/事件互相一致、与用户现实区分、可在生活事件库检索；禁止作为现实记忆写进 A-Memorix。

### 统一微信通道
- 微信仅作为本人个人私聊的自然对话入口；不做群聊，也不设计管理命令或聊天内审核。插件开关、参数及数据维护通过 MaiBot 插件后台/配置完成。部署后检查微信 session 的 `logs/maisaka_prompt/...json` `request_items` 与真实收发，确认拟人上下文只注入本人私聊且不串会话。

### 短期记忆与 A-Memorix 日沉淀
- 会话窗口/事件暂存仅为短期记忆；每日收束生成结构化候选，先分类、引用原始消息证据、去重合并、标置信度/时间/来源及是否被用户纠正。
- `user_fact` / 稳定偏好候选在后台保留证据、去重和冲突检查；仅用户预授权的低风险类别可自动写入受支持的 A-Memorix 接口。敏感、含糊、冲突项静默隔离，不通过微信请求审核。
- `persona_fiction` 只归档到独立生活事件库，形成昨日事件摘要、未完事项、心境变化和今日计划，不同步 A-Memorix。推测不自动升格现实事实；候选可静默隔离或过期。
- 每日任务要幂等（日期+bot+user scope）、失败可重试、留最小审计摘要。当前已知 A-Memorix WebUI Host proxy 是实测 API 路径但非已确认稳定的插件公开契约；优先找 1.4.5 官方 SDK/Host API，未确认前不要直接 SQL 写库；只在用户预授权的低风险类型上考虑后台自动写入，其余留本地静默候选，不要求聊天确认。

### SubQ 决策器与成本预算
- SubQ 是统一的 JEV 式决策模型，不单独设第二套 Judge/Evaluate/Verify。确定性规则优先；只在语用有歧义、模拟生活事件需选择/验证、记忆候选需升格时调用，不对每条消息做第二次 LLM。
- 免费/低成本本地逻辑先过滤非本人/非私聊事件、重复消息及确定性明确请求；SubQ 仅处理有歧义且值得额外判断的难例，返回短 JSON：`action`、`reason_code`、`confidence`、`context_refs`、`ttl`。不生成最终回复。
- 生成主回复仍用 MaiBot 配置的模型；antibait 仅在质量检查确有价值时最多重试一次；humanizer 不做硬截断；MaiWeave/生活引擎不额外触发未经门控的主动消息。每日生活/记忆整理合并批处理，事件按阈值或批量调用 SubQ，设 token/日预算、超时、缓存与幂等。
- SubQ 超时/异常/坏 JSON 时入站回复回退 MaiBot 既有 Replyer；后台事实任务标记重试/静默隔离，不能依不完整结果写库。明确提问/点名/求助不得静默吞掉。影子模式起步，以漏答率、误静默率、成本和微信端到端延迟决定启用阈值。

### 组件职责融合
- MaiWeave：只参考生活状态、日程、关系和事件连续性的设计思路；生活引擎及代码由本项目独立设计实现，不依赖 MaiWeave 插件、代码或数据库。既有 0.11.8 只作为当前环境基线，部署自研实现时需避免重复注入。
- 拟人核心：MaiBot 原生人格读取、短期情绪/精力及关系状态、虚构生活边界、个人私聊入口硬过滤和后台日结候选账本；不设计微信控制命令。
- SubQ：歧义决策、模拟事件一致性审核、记忆候选升格建议；不写回复、不直接写数据库。
- A-Memorix：用户现实事实与稳定偏好的长期记忆；只经受支持接口协作，后台写入遵守预授权低风险范围与证据闸门，不增加聊天审核。
- private-humanizer：可选择保留风格/表达层，关闭重复主动续话和硬截断；antibait 可保留为生成后质量闸门但需实测避免重复重生成。
- life-behavior-reference：按用户问题按需检索，作为建议性知识，不作为角色亲历事件。

## MaiBot 适配原则
- MaiBot A-Memorix 继续做真实事实/人物记忆；拟人插件只存短期虚拟状态与候选推断。当前官方 SDK 文档未公开 A-Memorix 专用读写代理，不能私写内部 DB。
- 每条状态/记忆演化要有来源、置信度、时间衰减和验证；稳定人格唯一来自 MaiBot 当前生效的 `[personality]`，插件只存可衰减的动态状态，不另建人格演化版本。
- 先做观测与回归测试，再加情绪/生活；主动分享属于远期可选项，默认关闭，并受私聊对象、频率、冷却与安静时段硬限制。
