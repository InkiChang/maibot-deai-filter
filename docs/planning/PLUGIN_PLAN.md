# MaiBot 个人拟人插件：前期规划

**状态：** 规划稿，尚非实现规格。
**目标部署：** 用户本人使用的 MaiBot 1.4.5；唯一目标为经授权的微信个人私聊。
**实现原则：** 自研插件代码、数据模型与行为内容；从参考项目提炼设计，不依赖它们的代码、运行时或数据库。

## 1. 项目目标与非目标

### 目标

建立一个具有稳定人格、连续自主生活经历、可演化短期状态、长期记忆协作和自然沟通能力的个人 AI 角色。生活系统在后台持续推进角色日程、关系和事件；角色在对话中将这些作为自身生活经验自然回忆。微信仅作为自然对话入口；插件参数由 MaiBot 后台配置，不要求用户在聊天中执行审核或管理命令。

### 非目标 / 硬边界

- **不处理群聊。** 插件在入口处拒绝群消息及非授权用户；不做群聊门控、群体关系建模或群聊主动发言。仅靠 MaiBot 全局配置不够，插件自身还需按平台、私聊标志、用户 ID 和会话 ID 做硬校验。
- 不修改 MaiBot 核心源码，不直接读写 A-Memorix 内部数据库，不假设 QQ 专用 API 可用于微信。
- **角色生活采用沉浸式主体视角**：角色在日常对话中可自然把连续生活、关系经历和梦境当作“我”的经历来回忆，不必主动声明是模拟。系统内部仍保留来源/世界标签并与用户现实事实分账；涉及现实世界可验证事项时（例如声称现实中亲自到过某地、已执行物理行动、已发出消息/承诺，或实时看见天气新闻），不得伪称发生。用户明确询问现实能力或行动是否真的发生时，清楚说明边界，不用日常免责声明打断沉浸感。
- 不让模型自行改写稳定人格、现实事实、授权范围或安全规则。
- 不要求每条消息调用 SubQ，也不以第二个模型生成最终聊天文本。SubQ 是插件独立决策服务，拥有自己的 Provider/模型/端点/凭据引用配置；MaiBot 现有普通模型配置不提供决策模型槽位。

## 2. 核心概念：两本账、一个人格

1. **现实记忆账（A-Memorix）**：用户明确提供的事实、稳定偏好、重要计划等。后台写入须保留来源证据；仅对用户预授权的低风险类别自动写入，敏感、含糊或冲突项静默隔离。
2. **角色生活账（插件自有存储）**：角色自己的连续生活经历，包括日程、事件、情绪变化、未完成事项和梦境。角色可从第一人称自然回忆和谈论这些经验，无需日常声明其为虚构；系统只在内部标注来源/世界类型，并与用户现实事实账隔离，不写入 A-Memorix。现实世界物理行动和外部事实另作来源校验。
3. **稳定人格（MaiBot 原生设定）**：身份、价值观、语气、关系边界、兴趣和禁区以当前生效的 MaiBot `[personality]` 为唯一事实源；插件不另存/演化第二份人格。插件只计算可衰减的短期状态调制，后台配置的人设变更仍由 MaiBot 原生管理。

每条可持久化记录至少有：`id / owner_scope / kind / source / evidence_ref / created_at / valid_at / confidence / status / privacy / expiry / version`。只允许本人私聊作用域，不能跨用户或跨会话泄漏私密上下文。

## 4. SubQ 使用边界与经济策略

SubQ 是唯一的决策模型，不拆成多个独立 Judge/Evaluate/Verify 模型。调用采用 **确定性优先、疑难才问、短输入短输出**：

### 不调用 SubQ
- 微信身份/私聊授权、重复消息、定时窗口和每日额度等可由代码准确判断的事项。
- 明确问题、明确请求、直接点名：直接交给 MaiBot Replyer，避免多一跳延迟。
- 每条消息的情绪数值更新：先由轻量规则/状态转移完成；只在低置信度且会影响重要行为时升级。

### 值得调用 SubQ
- 输入意图有歧义，需判断简短回答、延后或补充上下文；但不得因低置信度吞掉明确问题。
- 角色是否分享某段主体生活经验，以及它与既有时间线是否连贯；涉及现实物理行动、地点或实时外部事实时另做证据与能力边界校验。
- 每日批处理时对去重后的记忆候选做一次合并筛选，不能每条候选都单独请求。
- 用户主动要求生活规划/角色计划，而多种选择会影响连续性时。

### 预算、请求重试与失败策略
- 优先本地规则；SubQ 只用于影响显著且规则无法判定的少量事件。SubQ 通过插件独立决策模型客户端调用；记忆整理/生活生成等任务按需复用 MaiBot 已配置模型。两类调用分别统计预算与错误，不以更换凭据绕过任一服务的限流或配额。
- 只传必要文本片段及已选上下文，不发送完整聊天历史、记忆库或生活账。输出短 JSON `action / reason_code / confidence / context_refs / ttl`；`action` 按具体任务白名单校验，不包含回复正文或写库指令。
- 按任务缓存结果；设单次超时、输入/输出 token 上限、全局日预算和 cost ledger；日常状态更新、生活排程、行为模板匹配、确定性去重优先用代码/批处理。
- 当前实现边界（P3-10）：SubQ 客户端有进程内 UTC 日账本，按调用方估值原子预留请求数、Token 与费用；每次重试重复计入，额度不足时拒绝请求。账本不持久化、估值非服务商实账单，且尚未接入 MaiBot Hook 的确定性降级；上线前仍须实现并实测。
- 对 SubQ 独立客户端的超时、连接中断、HTTP 5xx 等暂时性错误可做有限重试：指数退避并加入随机抖动，尊重服务商返回的 `Retry-After`；重试次数、总耗时和费用纳入 SubQ 预算。默认最多额外重试 1 次（总尝试上限 2 次），达到任一上限立即停止。复用 MaiBot 的后台任务遵从 MaiBot 调用层的重试策略，不再套一层重复重试。
- **禁止重试层叠**：SubQ 使用独立客户端，因此只由该客户端统一管理 SubQ 请求重试；不得再由上层插件/Hook 对同一请求重复包重试。复用 MaiBot 模型的后台任务与主 Replyer 由 MaiBot 调用层负责重试，插件不额外叠加。所有任务均设置总尝试次数、总耗时和预算上限。
- HTTP 429/配额限制按服务商规则遵从 `Retry-After`，不得立即重试或通过更换凭据规避限制；认证/权限、模型不存在、请求参数错误等永久性错误不自动重试。结构化输出格式错误可在预算允许时最多进行一次短格式修复请求，不把无效结果当有效决策。
- 只对无副作用的模型请求重试。后台写入必须幂等：用任务/批次 ID 防止重复写事实或事件；模型请求成功但响应丢失时，先查任务状态或安全重跑纯生成，不重复执行写入。
- 达到重试上限、超时、无效响应或模型不可用时：SubQ 决策任务回退确定性规则，主聊天仍交由 MaiBot Replyer；明确问题不因 SubQ 阻塞。后台记忆/生活任务标记待重试或跳过，绝不依据不完整结果写入事实或发送消息。
- 先影子运行，衡量决策质量、漏答、成本、重试率及延迟，再逐步启用低风险决策。

### 4.1 统一动态拟真算法（规则主导，SubQ 仲裁）

每轮按以下闭环计算，状态与人格分层，不靠每轮 LLM“演情绪”：

1. **感知与归因**：从本人私聊新消息、近期话题、角色生活记忆、定时天气/新闻素材中提取少量事件。事件在后台记录来源、时间、置信度和经验类别（角色日常/梦境/用户明确事实/外部资讯），供检索、归档和现实事实核验；前台将角色日常和梦境作为角色自己的连续经验，不因内部分类而反复称其为虚构。没有证据的外部事实不写入现实事实域。
2. **状态衰减与刺激更新**：情绪向人格基线回归：`x(t)=baseline+(x_prev-baseline)*exp(-Δt/τ)`；新事件按强度、置信度和人格相关性加入有限刺激，随后裁剪至范围。精力、压力、无聊各用不同 `τ`；规则每日/收到消息时运行，成本近零。
3. **生活与行为候选**：日程/天气/近期事件生成少量候选行动（继续手头活动、休息、关注某资讯、回应用户等）；情境行为库只给匹配场景提供动作模板。梦境作为角色自身梦境经验进入生活连续性；后台用 `experience_type=dream` 与清醒生活、用户现实事实分账，不在日常表达中称其为虚构。
4. **候选评分与取舍**：代码按人格一致性、当前需求/关系、状态适配、事件连续性、话题相关性加分；按现实冲突、重复、越界与打扰风险扣分。若最高候选明显胜出，直接采用；候选分数接近且选择会实质改变回复/生活连续性时，才让 SubQ 对这组短候选做仲裁。明确提问始终走 Replyer，不因打分而静默。
5. **表达调制**：把选定状态转换成最多几条简单控制信号（如“语气稍轻松”“沿用当前话题”“不主动扩展”），叠加到 MaiBot 原生 `[personality]`；不复制或覆盖其稳定身份、价值观、底线。
6. **反馈学习**：回复和后续互动只更新短期状态/话题连续性；用户明确偏好可进后台事实候选；角色生活事件更新角色自有生活账，作为其后续可回忆的主体经验。后台来源类别用于防止把用户事实、外部资讯和角色经验串账；不要求角色日常把自身生活称作模拟。避免把一次反应永久固化成新人格。

现实天气/新闻按定时批量搜索并缓存（建议先每天最多一批新闻、天气按有效期刷新；无可用搜索接口则跳过，不额外反复搜索）。后台记录来源、地区、发布时间和过期时间；素材可融入角色当天环境、兴趣与生活话题，成为角色连续经验的一部分。过期信息不再注入；涉及“现实中此刻天气如何/角色实际上在哪里”等明确事实问题时，按来源和能力边界回答。

### 4.2 按功能分工的模型调用

模型调用遵循“确定性优先、任务分槽、按任务选择合适连接”。主聊天回复由 MaiBot 原有 Replyer 负责；SubQ 是插件独立决策模型模块，因为 MaiBot 没有独立决策模型配置项，故由插件保存 Provider/API 兼容类型、Base URL、模型名、密钥引用及专属预算。记忆整理、生活生成等后台生成任务可复用 MaiBot 已配置模型，但必须通过公开 Host 接口；不得私读数据库或复制 MaiBot 凭据。

| 功能 | 是否需要模型 | 默认处理 | 可选模型分配 | 频率/降级 |
|---|---|---|---|---|
| 微信主聊天回复 | 需要，但由 MaiBot 原有 Replyer 负责 | 使用 MaiBot 当前会话主模型，插件注入精简状态/上下文，不另起一遍生成 | 由 MaiBot 主配置管理；插件只读显示，不另设副本 | 每次正常对话一次主回复 |
| 歧义/重要决策 SubQ | 需要 | 明确问题不调用；规则判不清且影响显著才短输入、短 JSON 调用 | 插件独立 SubQ 模型配置：Provider/API 兼容类型、Base URL、模型名、凭据引用；与 MaiBot 普通模型槽位隔离 | 低频；SubQ 专属预算，超预算/失败回退规则及 Replyer |
| 用户事实抽取、去重、冲突候选 | 语义抽取可能需要；规则去重不需要 | 本地规则筛选、证据提取、批量处理优先 | 可选择 MaiBot 已配置模型；如无公开调用接口则仅规则处理，不复用 SubQ 私有连接 | 后台批次；模型不可用时留候选/跳过，不自动写入 |
| 角色生活日结、事件/日程生成 | 生成自然连续生活时可能需要 | 时钟推进、状态衰减、日程规则由代码完成 | 可选择 MaiBot 已配置模型；宿主接口不可用时跳过模型生成 | 低频批量生成；预算不足则减少/跳过，不影响聊天 |
| 梦境生成 | 高发散内容生成需要 | 低频后台触发，不与每轮聊天绑定 | 可复用 MaiBot 已配置的生活生成模型；无可用 Host 接口时跳过生成 | 预算不足直接跳过；梦境仍只进角色生活账 |
| 天气/新闻 | 获取信息靠搜索工具，不因检索本身需要模型 | 定时采集、来源/时效校验与缓存用代码 | 仅在需摘要或转为角色话题时可复用 MaiBot 已配置的生活生成模型；不是每次搜索都调 LLM | 合并批处理；无搜索工具或素材过期则不注入 |
| 情绪、精力、关系数值、记忆检索/排序、时间衰减、token 预算 | 不需要 | 规则、公式和本地检索 | 不设模型槽，避免将简单确定性任务交给 LLM | 每轮轻量执行或按需执行 |
| 回复质量检查/改写 | 首版不需要额外模型 | 确定性规则检查，默认关闭重生成 | 未来若确有收益，可复用 MaiBot 已配置的普通模型（若公开 Host 接口可用），不调用 SubQ；必须独立预算、最多一次 | 默认不产生第二次生成；失败不阻塞回复 |

### 4.3 上下文与模型预算

- 每轮只拼一个紧凑 context card：情绪/精力/关系多轴状态的短标签及变化方向、当前生活事件（至多 1 条）、最相关事实/短期摘要（少量）；不传完整状态表、整本行为库、整份日报或历史原文。
- 记忆检索按 relevance × recency × confidence 排序，并对低重要性细节渐进衰减；去重后只取少量片段。设硬 token 上限，超限按“当前用户消息与系统硬规则 > MaiBot 原生人格 > 明确相关事实/承诺 > 当前关系/状态摘要 > 生活事件/新闻 > 行为模板/装饰背景”顺序保留，先压缩或删低优先级素材，绝不截断当前消息。
- Prompt 分层压缩只保留核心事实和摘要，不以截断字符串破坏关键信息；MaiBot 原有系统规则和人格段始终不由插件压缩覆盖。
- SubQ 输入只含决策所需的短上下文、少量候选和输出 schema；缓存同一事件判决。普通明确对话、状态衰减、日程、行为模板匹配均不调 SubQ。
- 天气/新闻用定时合并采集与缓存，不按每条聊天触发搜索；过期或来源不明时宁可不注入。日结尽量批量执行且可用规则先筛。
- 监控每轮 prompt token 增量、搜索次数、SubQ 次数/令牌/费用、其他 MaiBot 模型任务用量、重试率和回复延迟；SubQ 与 MaiBot 模型任务分别设预算。任一任务达预算则仅关闭/降级该任务，不继续堆上下文或重试；主 Replyer 按宿主自身策略运行。

## 5. 端到端衔接

### 微信私聊回复

```text
微信个人私聊事件
  → 本人/私聊硬闸门（不通过即丢弃，不调用模型）
  → 规则预处理与状态衰减更新（代码，不调用 SubQ）
  → 仅歧义且影响显著时调用 SubQ；明确问题直接进入主流程
  → Context Budgeter 选择：当前消息 + 极短状态卡 + 最多少量相关记忆/生活事件
  → MaiBot 原有 Replyer 生成最终回复
  → 可选质量规则（默认代码检查；确有价值才最多一次重试）
  → 微信私聊发送
  → 异步追加最小事件记录，后台批量做事实候选与角色生活日结
```

### 每日收束

```text
本人当天对话与短期状态（异步后台）
  ├─ 用户现实事实/稳定偏好 → 证据定位、分类、去重/冲突检查 → 高置信低风险且授权范围内才写入（若有受支持 Host 接口）
  │   → 含糊/敏感/冲突项静默留在隔离候选库，不聊天打断、不自动写入
  └─ 角色生活/情绪/梦境/资讯体验 → 按内部来源元数据归档、去重压缩与时间一致性检查 → 独立角色生活账
      → 后续按相关性取少量自传式经验摘要；天气/新闻素材保留外部来源与时效元数据，可融入角色当天经历；前台不显示内部类别标签
```

## 6. 数据域与写入规则

- `owner_scope` 固定绑定单一用户 ID + 私聊 session；任何读写先校验此 scope。
- `reality_memory`：只收有证据的用户事实/偏好；记录原文消息引用或来源 ID。推断不得伪装事实。
- `persona_experience`：角色自己的生活经历，含时间、状态、事件前置条件、后果及是否已向用户讲述；后台记录 `experience_type`（日常/梦境/资讯触发等）与来源，用于记忆检索和现实事实分账，不作为日常回复中的自我揭假标签。
- `state_snapshot`：情绪/精力等短期态，包含变化原因和衰减时间；可重算，不作为永久人格事实。
- `persona_modulation_state`：不复制 MaiBot 稳定人设；记录短期状态及由状态导出的临时表达调制，含原因、时间戳和衰减参数。
- `memory_candidate`：来源、原文消息引用/哈希、类别、置信度、敏感度、冲突项、处理状态（自动写入/静默隔离/过期）；高风险项不因模型置信度高而自动升级。
- `persona_experience`（含日常、梦境及资讯引发的经历）与用户现实事实分表或逻辑强隔离；天气/新闻保留 URL/来源、抓取时间、地域和有效期，可成为角色生活素材，但不得伪装成未经工具支持的实时观察或现实物理行动。
- 生活库和 A-Memorix 必须物理/逻辑分域；禁止把整份角色日报或梦境直接导入 A-Memorix。

## 7. 个人私聊边界、后台配置与隐私

- 只允许配置的本人微信身份和私聊会话；群聊与其他用户消息由入口硬拒绝，不读状态、不注入上下文、不调用模型。
- 会话数据按本人 scope 隔离；默认不留完整聊天原文，后台任务仅保留必要的来源引用/哈希及脱敏候选。
- 不设计微信管理命令。各任务模型选择、日志和模块开关从 MaiBot 插件配置/后台维护；模型凭据完全由 MaiBot 管理，本规划不要求用户在微信中审核记忆。
- 现实记忆自动写入只允许用户预先授权的低风险类别；敏感、含糊、冲突候选静默隔离，不通过机器人主动打断。需定期清理候选和过期外部素材。
- 主动分享默认关闭；若未来启用，受每日不超过 10 次、接收对象、冷却和安静时段配置约束；SubQ 不能放宽硬限制。

## 8. 开发阶段与阶段退出标准

### Phase 0：接入验证与基线
- 验证 MaiBot 1.4.5 插件 SDK、Hook 顺序、微信事件结构、私聊/群聊识别、微信 Prompt 注入位置。
- 建立本人白名单硬闸门；记录/查看微信 `logs/maisaka_prompt/<session>/<epoch>.json` 的 `request_items`，确认仅个人私聊收到插件注入。
- 退出标准：群消息及未授权用户零模型调用、零状态读取；本人微信私聊端到端测试可复现。

### Phase 1：人格调制 + 观测 + SubQ 影子模式
- 读取 MaiBot 当前生效 `[personality]`，插件仅计算短期调制卡；建立私聊短期摘要和小型回归集；实现 SubQ 独立连接配置的安全读取、连通性诊断与影子决策，不改变回复。SubQ 配置与 MaiBot 主回复/后台任务模型选择分别配置、分别统计。
- 退出标准：明确问题漏答不增加；Prompt 增量有上限；每次模型调用有理由/预算记录；超时、瞬时错误和永久错误按策略分类，重试后仍失败能安全回退。

### Phase 2：情绪状态、表达与成本基线
- 实现规则驱动的情绪/精力/压力衰减，接入精简状态卡和可开关表达检查；采集各任务模型槽位、token、请求次数、重试次数、错误类别、延迟与预算消耗。
- 退出标准：上下文增量有硬预算；状态错误不会污染事实记忆；质量收益有对照样例且推理成本在预算内。

### Phase 3：角色生活连续性、行为策略与现实素材
- 自研日程/生活事件、情境行为模板和高发散梦境；天气/新闻通过验证过的 MaiBot 搜索能力定时采样并缓存。先只在微信回复相关话题时按需取用，不开启主动分享。
- 退出标准：角色生活与梦境在跨重启后保持连续且可自然第一人称回忆；后台经验类别/外部来源可追溯并与用户现实事实分账；过期资讯不再使用；不相关话题无额外上下文注入。

### Phase 4：每日后台收束与 A-Memorix 协作
- 日结分流用户现实事实候选与角色生活经验摘要；角色经验留在独立生活账，用户事实候选仅在已验证 Host 接口、属于预授权低风险类别且证据充分时自动写入。其余静默隔离/过期，不发微信审核卡。
- 退出标准：任务幂等可重试；证据可追溯；冲突/敏感项不会自动写入；无完整聊天原文留存。

### Phase 5：可选主动生活分享（远期，默认关闭）
- 首期不主动发消息；若未来单独启用，仅在本人私聊目标内按明确事件、冷却、安静时段和每日≤10次限制执行，决策仍遵从 SubQ 预算及硬规则。
- 退出标准：后台可关闭；不会群发或跨用户；角色可自然分享自身生活经验，但不声称现实中已执行未发生的物理行动，不重复打扰。

2. 哪个 Hook 最适合在主模型调用前拦截/注入，是否能安全暂缓/取消 Replyer；若 Hook 不支持可靠中止，首版将 SubQ 限为上下文选择/状态建议，不做静默拦截。
3. MaiBot 1.4.5 当前公开 SDK/Host 是否提供稳定的 A-Memorix 写入/查询接口。未验证前只在插件本地保存静默候选，不直接写 SQL，也不依赖未公开 WebUI endpoint。
4. 微信只作为普通私聊对话入口；插件不要求用户使用管理命令或消息卡片。
5. SubQ 独立 Provider 的协议兼容性、价格、上下文窗口、结构化输出能力、并发、凭据注入和超时需按所选服务实测，并据实设独立预算。

## 11. 验收总原则

- 个人私聊功能全链路可从微信访问；群聊完全不纳入功能范围，并由代码硬拒绝。
- 用户现实事实与角色主体经验可追溯、分域；后台来源标签不进入日常叙述。管理侧具备必要的查询、更正/删除能力，不要求通过微信命令操作。
- 角色稳定人格与短期状态互不混淆；角色生活经验跨会话连续、可自然第一人称回忆；现实能力与实际物理行动的边界仅在相关问题中准确说明。
- SubQ 调用有明确理由、预算可观测、失败回退，不替代 MaiBot Replyer。
- 每项功能可独立开关；通过真实微信 Prompt 快照、行为样例、成本与隐私检查后才扩大使用范围。
